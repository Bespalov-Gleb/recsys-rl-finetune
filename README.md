# RL-дообучение последовательного рекомендателя по модели награды (Yambda-50M)

Как устроен эксперимент:
1. GPT-2 учится предсказывать следующий трек.
2. Reward model предсказывает реакцию пользователя на рекомендацию: долю прослушивания, listen+, лайк, продолжение
   сессии, «принятие» нового трека.
3. Политика дообучается с KL-регуляризацией: GRPO-подобный policy gradient, многошаговый вариант, DPO,
   Positive-CE.
4. Всё сравнивается с точным решением той же задачи, π* ∝ π_ref·exp(r/β).

Оценка:
- одно глобальное разбиение по времени;
- релевантность — на реальных будущих прослушиваниях;
- награда — независимым gold-судьёй, которого политика не видит.

**Отчёт:** [REPORT.md](REPORT.md) (то же с картинками внутри — [REPORT.html](REPORT.html)).

## Главное

Тест, 22 890 контекстов, разность с базой и 95 % ДИ парного бутстрепа по пользователям. «Открытия» — Recall@10
по дослушанным трекам, которых пользователь раньше не слушал.

| модель | KL | HR@10 next | Recall@10 дослушанных за сутки | Recall@10 скипов | открытия | gold: доля прослушивания |
|---|---|---|---|---|---|---|
| GPT-2 base | 0 | 0,193 | 0,142 | 0,101 | 0,036 | 0,575 |
| **π*, β=1** (переранжирование топ-1000) | 0,07 | **+0,002** | **+0,007** | −0,000 | **+0,001** | +0,011 |
| **π*, β=0,3** | 0,41 | −0,002 | **+0,015** | −0,002 | +0,001 | +0,029 |
| GRPO на GPT-2, β=0,3 (3 сида) | 0,07 | **−0,006** | **−0,001** | **−0,003** | — | +0,006 |
| GRPO на GPT-2, β=0,1 | 0,27 | **−0,018** | **−0,005** | **−0,009** | — | +0,013 |
| дистилляция π* в GPT-2 | 0,12 | **−0,008** | **−0,001** | **−0,004** | — | +0,006 |
| **GPT-2 + cross-голова, GRPO β=0,3** | 0,05* | **+0,004** | **+0,014** | **+0,002** | +0,001 | +0,016 |
| GPT-2 + cross-голова, GRPO β=0,1 | 0,49* | **−0,004** | **+0,027** | **+0,005** | −0,002 | +0,038 |
| эвристика «повтори любимое» (контроль) | — | **+0,009** | **+0,032** | **+0,030** | **−0,022 (−62 %)** | +0,024 |
| Positive-CE | 0,08 | +0,001 | **+0,003** | −0,001 | — | +0,003 |

\* KL внутри топ-1000. Жирным — разности, значимые по бутстрепу (95 % ДИ не содержит 0). Все разности gold
значимы. Для Recall скипов рост — это плохо.

- **RL-дообучение самой GPT-2 не работает:** при любых настройках она значимо теряет релевантность. Причина —
  выразимость: награда меняется от трека к треку из-за признаков «пользователь × трек», а выход «контекст ×
  эмбеддинг трека» их почти не выражает (отложенный R² 0,12 против 0,60 у собственных лог-вероятностей модели).
- **Если дать политике эти признаки**, тот же GRPO начинает работать. Маленькая голова над топ-1000 значимо
  улучшает HR, Recall и gold, не трогая открытия, и не эксплуатирует ошибки модели награды: proxy и независимый
  судья растут одинаково.
- **Офлайн-Recall легко выиграть повторами:** двухпараметрическая эвристика даёт наибольший прирост Recall, но
  на 62 % режет открытия. На треках, которые пришли через рекомендации сервиса и были дослушаны, она вдвое хуже
  базы (−54 %). π* при β=0,3 там же даёт +7 % (по новым трекам +11 %), cross-политика +3 %. Полезная часть модели
  награды — избирательность (дослушают или пролистают) и сохранение открытий.
- **Взлом награды зависит от её формы:**
  - доля прослушивания → короткие треки;
  - секунды → один 35-минутный трек всем;
  - лайки → несколько хитов в 13–22 % списков;
  - сильная оптимизация с персональными признаками → 97 % знакомых треков.

  Без KL GRPO за 250 шагов схлопывается в один трек. Ограничение «только топ-1000 базовой модели» — главный
  практический регуляризатор.
- **Генерация пяти треков подряд** зацикливается: 75 % повторов уже на втором шаге, в данных — 2,7 %. Оценка
  награды за k-й трек зависит от непроверяемого допущения о реакции на предыдущие рекомендации.
- **Устойчивость:** 11 автотестов на утечку; разброс по сидам ~0,001 HR@10; выводы те же, если история строго
  раньше по времени (у 19 % соседних прослушиваний одинаковая 5-секундная метка).

## Как воспроизвести

Python 3.11, зависимости — в `requirements.txt` (torch с CUDA ставится из индекса PyTorch). Данные: `yandex/yambda`
на Hugging Face, `flat/50m/multi_event.parquet` и `artist_item_mapping.parquet`.

```bash
mkdir -p data/raw/yambda_50m
curl -L -o data/raw/yambda_50m/multi_event.parquet https://huggingface.co/datasets/yandex/yambda/resolve/main/flat/50m/multi_event.parquet
curl -L -o data/raw/yambda_50m/artist_item_mapping.parquet https://huggingface.co/datasets/yandex/yambda/resolve/main/artist_item_mapping.parquet
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu128
RAW=data/raw/yambda_50m PY=.venv/Scripts/python bash scripts/reproduce.sh
```

Всё считалось на ноутбуке: i7-12650H, 16 ГБ RAM, RTX 4060 Laptop 8 ГБ, около 15 часов GPU. Тяжёлые задачи —
строго по одной на GPU.
